# Ergouzi Docs Top Header Single-Column Layout Spec

## 1. 结论

下一步布局改版，应该明确放弃当前的左右栏文档布局，改为：

- 顶部固定 Header 承载主导航
- 主内容区采用单列下沉布局
- 首页像产品化入口页
- 正文页像现代教程页，而不是传统文档后台页

参考方向：`https://recopy.pages.dev/`

不是照搬它的内容，而是借鉴它的结构逻辑：

- 顶部导航轻量固定
- Hero 区承担第一屏识别
- 页面内容按区块向下展开
- 全站阅读重心在中间主列，而不是左侧菜单

## 2. 为什么不继续左右布局

### 2.1 当前问题

当前左右布局虽然适合传统技术文档，但不适合我们这次目标。

这次我们不是在做“API reference 手册”，而是在做：

- 配置教程
- 平台接入说明
- 新手分流入口
- 面向普通用户的图文引导

这类内容更像“教程型产品站”，不是“开发者后台文档树”。

### 2.2 左右布局的几个问题

1. 页面一上来就显得太“后台”。
2. 左侧导航抢占了过多视觉权重。
3. 首页分流、教程引导、图文说明会被侧栏切碎。
4. 移动端上左右结构天然要塌陷，逻辑不如顶部导航清楚。

### 2.3 更适合的结构

顶部固定 Header 更适合当前产品形态，因为它把导航退回到“全站切换层”，而不是一直压着正文。

换句话说：

- Header 负责“去哪”
- Hero 和内容卡片负责“看什么”
- 正文页面负责“怎么做”

## 3. 参考站点拆解

参考 `recopy.pages.dev`，可以提炼出几个可借鉴点：

### 3.1 第一屏很克制

导航在顶部，不打断阅读。  
正文第一屏直接给出：

- 产品定位
- 一句核心价值
- 明确 CTA

这对我们的首页也成立。

### 3.2 内容是向下展开的

它不是依赖左侧树状结构驱动阅读，而是依赖页面内容节奏：

- Hero
- 特性说明
- 使用方式
- 细节补充
- CTA / footer

这说明单列主流布局完全可以承载信息密度，只要分段做得清楚。

### 3.3 视觉重心在中间

用户视线集中在中间主列，阅读体验更统一。  
这很适合图文教程和步骤说明。

## 4. 我们的新布局原则

## 4.1 全站原则

全站统一遵循：

1. 顶部固定 Header
2. 主内容单列
3. 分类切换靠 Header 和页面内入口
4. 不再长期占用左侧固定菜单

## 4.2 首页原则

首页只做：

- 分流
- 推荐路径
- 高频入口
- 快速说明

首页不做：

- 全量教程正文
- 长篇平台配置步骤
- 大量 FAQ 堆叠

## 4.3 正文页原则

正文页采用“宽中列 + 页内段落导航”的方式，而不是左侧树状文档页。

正文页重点是：

- 标题清楚
- 摘要清楚
- 步骤分段
- 图片顺序稳定
- 下一步入口明确

## 5. 新布局结构

## 5.1 顶部固定 Header

Header 固定在顶部，用来承载全站导航。

建议结构：

### 左侧

- 品牌标识
- 站点名称

### 中部

- 一级菜单
  - 开始
  - 基础教程
  - 应用接入
  - API 接入
  - SDK 接入
  - 示例
  - FAQ

### 右侧

- `CC Switch` 快速入口
- 旧版参考入口
- 未来可预留搜索按钮

Header 应该是：

- 固定但轻薄
- 半透明或柔和玻璃感
- 不抢内容主角位置

## 5.2 首页结构

首页建议改成以下顺序：

1. Hero
2. `CC Switch 快速配置 Codex`
3. 路线分流卡片
4. 分类入口区
5. 新手推荐路径
6. 底部说明 / 旧版参考入口

### Hero 目标

Hero 不要只写“这是文档站”。

应该回答：

- 这是一个什么站
- 它能帮你解决什么
- 你应该先点哪

### `CC Switch` 快速区

保留短摘要，不展开成长教程。  
作用是：

- 给新用户最短路径
- 给首页一个明确主入口

## 5.3 分类页结构

分类页不再像旧站那样只是“目录集合”，而应更像专题页。

例如 `/apps` 页面：

1. 顶部标题和说明
2. 平台卡片网格
3. 推荐阅读顺序
4. 常见分支说明

这会让分类页本身也有信息价值，而不是纯跳板。

## 5.4 正文页结构

正文页建议结构：

1. 页头
2. 摘要区
3. 步骤区
4. 图片区
5. 常见错误
6. 下一步

顶部可以保留一个轻量的二级导航条，用于：

- 当前分类返回
- 当前教程标题
- 页内锚点入口

但不要恢复左侧固定目录。

## 6. 页内导航怎么替代左侧栏

放弃左侧栏后，不代表正文页没有导航。

建议用这几种方式组合：

### 6.1 顶部锚点条

正文页标题下方可以有一个水平锚点条，例如：

- 准备
- 步骤
- 图片
- 排错

这样用户能快速跳段，但不会回到传统双栏结构。

### 6.2 章节卡片化

步骤区块做得更明显，让用户靠视觉层级自然定位。

### 6.3 底部上一页 / 下一页

继续保留，用于线性阅读。

## 7. 视觉方向

既然布局不再是传统文档页，视觉也应该同步：

- Header 更轻
- Hero 更强
- 卡片更柔和
- 渐变更浅
- 主内容中列更突出

建议方向：

- 浅奶油底
- 淡蓝、薄荷、桃粉、奶紫的低饱和渐变
- 大圆角
- 卡片分层
- 轻微悬浮感

但注意：

- 不做厚重毛玻璃
- 不做大面积高饱和撞色
- 不做持续性装饰动画

## 8. 响应式规则

顶部 Header 方案在移动端更自然，但要提前定规则。

### 桌面端

- Header 固定
- 中间主列阅读
- 分类入口可多列卡片

### 平板端

- Header 收紧
- 一级菜单可换成横向可滚动

### 手机端

- Header 保留品牌 + 菜单按钮
- 一级菜单放入抽屉或下拉面板
- 内容保持单列

重点是：移动端不能退回“先压一个巨大侧栏再折叠”的旧思路。

## 9. 对当前代码结构的影响

当前阶段已经有：

- React 路由骨架
- 分类结构
- 首页分流逻辑

这些可以保留。

需要调整的是布局层：

### 要移除或弱化

- 当前固定左侧 `aside` 主结构
- 长期占位的侧边导航容器

### 要新增或重构

- 顶部固定 Header 组件
- Header 一级菜单
- 单列主内容容器
- 分类页顶部专题化布局
- 正文页页头 + 锚点条

## 10. 文件级改动建议

后续实现时，重点会动这些文件：

- `src/app/layout/AppLayout.tsx`
- `src/components/navigation/Header.tsx`
- `src/components/navigation/SideNav.tsx`
- `src/pages/home/HomePage.tsx`
- `src/pages/category/CategoryPage.tsx`
- `src/styles/layout.css`
- `src/styles/tokens.css`

其中：

- `SideNav` 大概率不再作为常驻布局核心
- `Header` 会升级为全站导航承载体
- `AppLayout` 会从双栏改成“顶部 + 单列内容”

## 11. 验收标准

这一轮布局调整完成后，应满足：

1. 全站不再使用左右固定布局作为主结构。
2. 顶部固定 Header 成为主导航承载体。
3. 首页成为单列产品化入口页。
4. 分类页不只是列表，而是有专题页结构。
5. 正文页不依赖左侧栏也能清楚阅读。
6. 移动端导航逻辑比当前双栏塌陷更自然。

## 12. 最终建议

这次不是“把侧栏搬到顶部”那么简单，而是一次页面心智重构：

- 从“传统文档后台”
- 变成“现代教程产品站”

如果继续沿用左右布局，即使颜色变好了，整体气质还是会像旧站升级版。  
只有把导航层级、视觉重心和内容展开方式一起改掉，才算真正重做了 UI。
