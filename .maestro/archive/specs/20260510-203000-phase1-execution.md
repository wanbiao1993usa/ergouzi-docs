# Ergouzi Docs Phase 1 Execution Spec

## 1. Goal

Implement phase 1 of the Ergouzi Docs rebuild with a gradual migration strategy.

This phase focuses on:

- setting up a new React-based frontend foundation
- preserving the old static docs as reference assets
- implementing clear route and menu structure
- building a new homepage that acts as a traffic router instead of a content dump
- adding a short `CC Switch 快速配置 Codex` text entry on the homepage

This phase does **not** include full migration of all documents.

## 2. Scope

### In scope

- Initialize `Vite + React + TypeScript`
- Build the new app shell and routing structure
- Create top-level routes:
  - `/`
  - `/start`
  - `/guides`
  - `/apps`
  - `/api`
  - `/sdk`
  - `/examples`
  - `/faq`
- Build a left navigation system driven by structured content metadata
- Build a homepage with:
  - hero section
  - quick path cards
  - `CC Switch 快速配置 Codex` short text block
  - category entry cards
- Add placeholder or summary pages for route groups so the navigation is already usable
- Preserve current legacy assets and documents for later migration reference

### Out of scope

- full content migration from `assets/content.js`
- complete markdown conversion of all tutorials
- complex search system
- automated migration scripts
- deleting the legacy static implementation

## 3. Constraints

- Existing `assets/` folder must remain available and reusable.
- Existing legacy static files must not be removed in phase 1.
- The new structure should make future markdown migration straightforward.
- The new homepage must not become a long tutorial page.

## 4. Acceptance Criteria

1. The repository contains a working React + TypeScript + Vite app.
2. The new app builds successfully.
3. The homepage acts as a route hub, not a full tutorial dump.
4. The homepage contains a short `CC Switch 快速配置 Codex` entry with a link to `/apps/cc-switch`.
5. Top-level category routes exist and render clearly.
6. A shared navigation structure exists and reflects the routing categories.
7. Legacy static files remain in the repository for reference.

## 6. Implementation Notes

- Use structured metadata instead of hardcoding a giant page array into the UI layer.
- Keep route boundaries clear:
  - category routes for different content areas
  - dedicated routes for tutorials like `/apps/cc-switch`
- Keep the homepage concise and high-signal.
- Do not migrate all legacy content into React during this phase.

## 7. Test Strategy

- Run install
- Run build
- Verify route rendering
- Verify homepage structure
- Verify `/apps/cc-switch` route exists
- Verify legacy files are untouched

## 8. Rollback Considerations

- Because legacy files remain intact, rollback is simply continuing to use the current static version.
- Phase 1 should avoid destructive edits to the legacy implementation.
