## 这篇内容解决什么问题

这篇文章只解决一件事：  
**把真正用于调用客户端、SDK 或 API 请求的 Token 创建出来。**

很多人会直接跳进客户端配置，但如果 Token 这一步没理解清楚，后面很容易出现：

- Key 能填，但模型调不通
- 价格和预期不一致
- 不知道为什么同一个账号下，不同 Token 表现不一样

所以正式创建前，建议你先已经看过：

- [账号与 Token 基础说明](/guides/token-billing)

## 创建前先记住一句话

> **令牌分组决定倍率，倍率又会直接影响价格。**

也就是说，创建 Token 时最重要的不是名称，而是：

- 这个 Token 放在哪个分组里
- 这个分组对应的倍率是多少
- 这个分组是否支持你要用的模型

如果你对“分组”和“模型支持”的关系还不确定，先回去看上一页，再回来创建 Token，会更稳。

## 创建流程概览

整个流程可以压缩成三步：

1. 进入控制台的令牌管理
2. 填写名称并选择分组
3. 提交并拿到可复制的 Token

> 一定要选择分组，目前最低分组是0.2折组，倍率为0.02。

## 第一步：进入控制台，然后进入令牌管理

先打开 Ergouzi 控制台，在左侧找到 **令牌管理**，然后点击 **添加令牌**。

这一页的作用是管理你所有可用于请求的 API Token。  
如果你后面要给不同客户端、不同项目、不同环境分开配置，这里也会成为你主要维护 Token 的地方。

![控制台中的令牌管理与添加令牌入口](/assets/token/step1.png)

## 第二步：填写名称，并选择令牌所在分组

进入创建弹窗后，先填写一个容易识别的名称，然后选择令牌所属分组。

这里最关键的是分组，因为它直接决定：

- 这个 Token 能调用哪些模型
- 调用时采用什么倍率
- 最终价格会是多少

### 名称怎么取更好

名称建议按用途来命名，比如：

- 客户端名
- 项目名
- 环境名

这样后面你在多个 Token 之间切换时，不容易混淆。

### 0.2折 是什么意思

如果你看到某个分组显示 `0.2折`，它的含义不是乘以 0.2，而是：

- 按官网价格的 `0.02 倍` 计费
- 也就是常说的 **0.2 折** 或 **0.02 倍率**

所以分组倍率越低，通常意味着价格越便宜；倍率越高，实际消耗就越高。

![创建令牌时填写名称并选择分组倍率](/assets/token/step2.png)

## 第三步：点击提交，得到 Token

信息填写完成后，点击提交，系统就会创建出新的 Token。

创建成功后，你会在令牌管理列表里看到这条记录。  
后续客户端、SDK 和 API 请求，都可以使用这个 Token 做鉴权。

你此时应该重点确认两件事：

1. 这个 Token 是否已经成功出现在列表里
2. 它对应的分组和倍率是不是你预期的那一个

![创建成功后的令牌管理列表](/assets/token/step3.png)

## 创建完成后接下来做什么

如果你已经完成这一步，下一步一般有两种情况：

### 你还没决定用哪个接入方式

那就先回去看具体路线：

- [CC Switch 配置 Codex](/apps/cc-switch)
- [OpenAI Compatible 接入](/api/openai-compatible)

### 你已经知道要接哪个客户端

那就直接把这个 Token 填进对应客户端、SDK 或 API 请求里。

## 常见注意事项

- 分组会直接决定倍率，倍率又会直接影响价格，创建前务必先确认清楚
- 截图里的 `0.2折` 表示官网价格的 0.02倍
- 名称建议按用途命名，后续在多个 Token 之间切换更清楚
- Token 创建完成后应及时保存，后续客户端、SDK 和 API 请求都会用到它

## 如果你创建完还是不能用

那大概率不是“创建按钮没点对”，而是下面这些问题之一：

- Token 分组不支持你当前要用的模型
- 你在客户端里填错了 Token
- 你理解成了“有 Token 就一定能用所有模型”

如果你遇到的是这种情况，优先回看：

- [账号与 Token 基础说明](/guides/token-billing)
