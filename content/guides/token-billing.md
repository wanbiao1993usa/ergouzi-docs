## 这篇内容为什么重要

很多人第一次接入时，最容易把下面几件事混在一起：

- **API Token**
- **令牌分组**
- **普通余额**
- **无限订阅**

如果这几个概念没先分清，后面就很容易出现这些典型问题：

- Token 建出来了，但模型不能用
- 余额已经充值了，但调用还是报 group 相关错误
- 开了订阅，却不知道为什么仍然要用 Token

所以这篇内容的目标不是教你点按钮，而是先把这套关系讲清楚。

> 一句话说明：**API Token 负责鉴权；令牌分组决定模型支持范围和价格；普通余额或无限订阅决定账号权益。**

## 先把四个概念拆开

### 1. Token 是调用凭证

Token 的作用只有一个：  
**让客户端、SDK 或 API 请求能够证明“这是你的账号在发起调用”。**

它不是：

- 余额
- 套餐
- 模型权限本身

也就是说，你即使已经有余额，或者已经开了订阅，真正发请求时还是要用 Token 做鉴权。

### 2. 分组决定模型与价格

Token 真正绑定的是一个 **令牌分组**。  
这个分组会直接决定两件事：

- 这个 Token 能调用哪些模型
- 这些模型按什么倍率计费

所以“Token 能不能用某个模型”，不是只看你有没有 Token，而是看这个 Token 所在的分组，是否支持那个模型。

### 3. 普通余额是按量扣费

如果你走的是普通充值路线，那么调用时会按模型价格和分组倍率去扣余额。

它更适合：

- 用量不稳定
- 想先小额试用
- 想按量控制成本

### 4. 无限订阅是账号权益，不是替代 Token

如果你开通的是无限订阅，账号会获得对应订阅权益。  
但这不代表你不需要 Token。

真正的调用链路依然是：

1. 客户端使用 Token 发请求
2. 系统读取 Token 所属分组
3. 再结合你的账号权益判断如何处理请求

所以订阅和 Token 不是二选一关系，而是两层不同职责。

## 你必须先知道的判断规则

在继续下面的操作前，先记住这四条：

- **Token** 是调用凭证，不是余额
- **分组** 决定模型支持范围和价格倍率
- **普通余额** 走按量扣费
- **无限订阅** 只是账号权益，实际调用依然要用 Token

如果某个模型不支持你当前 Token 的分组，最常见的表现就是：

- `No available channel`
- group 相关错误
- 模型明明存在，但请求直接失败

## 怎么看某个模型支持哪些分组

这个步骤非常关键，建议放在创建 Token 之前。

### 查看方法

1. 打开模型广场：<https://ergouzi.life/pricing>
2. 点击你准备使用的模型，比如 `gpt-5.3-codex`
3. 在右侧详情区域查看 **分组价格**
4. 看“分组”那一列里有哪些分组

那一列里出现的分组，才是这个模型真正支持的分组。

> 如果你的 Token 分组没有出现在该模型的“分组价格”里，就不要急着创建或继续排错，先换模型，或者换一个支持该模型的分组。

## 一个最容易犯错的理解误区

很多人会把“我已经有 Token”误解成“我应该已经能调所有模型”。

这其实不成立。

真正决定调用是否成功的链路是：

1. 你用 Token 发请求
2. 系统识别这个 Token 属于哪个分组
3. 系统检查这个分组是否支持当前模型
4. 如果支持，再按该分组的价格规则处理

所以最常见的错误，不是 Token 没创建成功，而是：

- Token 选错了分组
- 模型和分组对不上
- 没有先去模型广场核对支持关系

## 什么时候该回来看这篇

如果你后面遇到这些问题，说明应该回来看这篇关系说明：

- 模型调不通，但 Key 没问题
- 同一个 Key 有些模型能用，有些模型不能用
- 你不确定该买普通余额还是开订阅
- 你已经开订阅，但客户端仍然要求你填 Token

这些问题本质上都不是“按钮没点对”，而是对账号、Token、分组和权益的关系理解还不够清楚。
